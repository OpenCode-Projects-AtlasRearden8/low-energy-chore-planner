# Low-Energy Chore Planner

An ADHD-friendly, no-guilt chore planner sized to your energy. Pick your spoons, do one tiny thing, and let that count.

Built and maintained by **Asdale Dynamics, LLC** — beginner-friendly tools explained like a friend would. Learn more at [dylanasdale.github.io](https://dylanasdale.github.io).

## Why it is like this

Most chore apps quietly assume you woke up with a full battery and a streak habit. This one does not.

- **Tiny tasks.** Every task is one-sitting small. The add form nudges you ("Wipe the sink" beats "clean the bathroom"), and a *Make it smaller* button shrinks any title into a 10-minute starter version.
- **Energy levels (spoons).** Tell the app how many spoons you have today (1–5, a guess is fine). Everything you complete spends spoons, and the *Fits right now* list narrows to what your remaining energy can actually cover.
- **Streak-free, gentle progress.** No streak counters, no flames, no guilt. You get a rolling 7-day win count, an all-time total, and a two-week dot strip where empty days are labeled rest days, not failures.
- **"Just one thing" picker.** When choosing is the hard part, one button picks a random task that fits your remaining spoons — weighted toward the tiniest ones — with *Done it* and *No thanks, spin again* right there.
- **Offline by default.** A service worker caches the whole app, everything is stored in `localStorage`, and you can export or re-import a JSON backup any time. No account, no server, no network required after the first load.
- **Accessible.** Semantic HTML, visible focus rings, `aria-live` announcements, large touch targets, respects `prefers-reduced-motion`, and a high-contrast mode (pure black, 7:1+ text contrast) that also auto-enables when your OS requests `prefers-contrast: more`.

This is a life-admin helper, not medical advice.

## Run it

It is a static site: plain HTML, CSS, and vanilla ES modules. No build step, no dependencies at runtime.

```sh
# from this folder
python3 -m http.server 8000
```

Then open `http://localhost:8000`. Any static file server works (`npx serve`, nginx, GitHub Pages...). Opening `index.html` from the filesystem works too, but browsers restrict service workers and `/`-relative paths on `file://`, so local storage backup/restore is best enjoyed over a real URL. On `localhost` or HTTPS the app is installable (PWA): look for your browser's install prompt once the service worker activates.

## Tests

```sh
npm test
```

Runs 40 tests with Node's built-in runner (Node 18+): 30 covering the core logic (task normalization, spoon math, the picker's weighting and skip-done-today policy, streak-free win counts, date rollovers, storage sanitization and backups) plus a jsdom smoke test that boots the real `index.html` end-to-end — choosing energy, adding tasks, completing them, archiving, and toggling high contrast — to prove the app actually runs.

Extra verification script (`npm run verify`) cross-checks that every asset referenced by `index.html`, the PWA manifest, and the service worker precache list actually exists on disk, plus license/README/credit presence.

## Project structure

```
index.html            the whole app UI
css/styles.css        theme + high-contrast mode
js/core/planner.js    core logic (pure, imported by both app and tests)
js/core/storage.js    offline storage, sanitizing, backup import/export
js/app.js             rendering and event wiring
sw.js                 service worker (cache-first, versioned cache)
manifest.webmanifest  PWA install metadata
icons/                icons (SVG plus PNGs generated by scripts/make-icons.js)
scripts/make-icons.js dependency-free PNG icon generator
scripts/verify.js     static asset/reference checks
tests/                core tests + jsdom smoke test
```

When you change bundled files, bump `CACHE_NAME` in `sw.js` (e.g. `lecp-cache-v2`) so returning visitors get the update instead of the cached copy.

## Data and privacy

There are none to protect: no analytics, no network calls beyond loading the page itself, no secrets. Your tasks, history, and settings live in your browser's `localStorage` on your own device, and the backup file is a plain JSON file you choose where to keep.
